# Physical layout browser demo

Checkout-only example, not an npm export. It lays out a fixed text sample in a
module worker using the experimental Wasm API. Click a row for a scalar caret,
drag across rows and pages for selection, or switch the title to reflow in the
same session.

To try editing, choose **Open or reset DOCX sample**. Click text, enter a
string, and choose **Apply edit** to insert. Drag within one paragraph to
replace; leave the field empty to delete a nonempty selection. Choose
**Download current DOCX** to save the original or most recent accepted preview.
Reopening the sample starts again from the original fixture. There is no
arbitrary upload, keyboard editing on the page, or text copying.

## Build and serve

From the checkout root in Bash, with the `wasm32-unknown-unknown` Rust target,
`wasm-bindgen-cli` 0.2.130, and Python 3 on your system:

```sh
python3 tools/serve_layout_demo.py --port 8000
```

Use `python3 tools/serve_layout_demo.py --check` to build and stage without
serving. For a manual build equivalent:

```sh
(
set -eu
scratch=$(mktemp -d /tmp/opencode/rocx-layout-demo.XXXXXXXX)
trap 'rm -r -- "$scratch"' EXIT
demo=javascript/experimental-layout/demo
font=crates/rocx-layout/tests/fonts/DejaVuSans-subset.ttf
printf '%s  %s\n' ac6e1cd9abc68c06cd7a56ea128d79b55fc0af4bc0be247b9f3737bf01ee11e4 \
  "$font" | sha256sum -c -
cp "$demo"/{index.html,style.css,main.mjs,layout-worker.mjs} "$scratch/"
cp "$font" "$scratch/font.ttf"
cp crates/rocx-layout/tests/fixtures/physical-plain.docx "$scratch/sample.docx"
cp crates/rocx-layout/tests/fonts/LICENSE.txt "$scratch/FONT-LICENSE.txt"
cargo run --locked --quiet -p rocx-layout --example font_atlas \
  -- "$scratch/font.ttf" > "$scratch/font-atlas.json"
cargo build --locked --release \
  --manifest-path javascript/experimental-layout/Cargo.toml \
  --target wasm32-unknown-unknown --target-dir target
wasm-bindgen --target web --out-dir "$scratch/pkg" --out-name rocx \
  target/wasm32-unknown-unknown/release/rocx_js_experimental_layout.wasm
python3 -m http.server 8000 --bind 127.0.0.1 --directory "$scratch"
)
```

Open <http://127.0.0.1:8000/>. Stop the server to clean up the staging
directory. Wasm, the font copy, and the outline atlas
are generated or staged locally; no generated assets are checked in. See
the [pinned font's provenance](../../../crates/rocx-layout/tests/fonts/README.md).

## Browser smoke

Run the deterministic main-thread protocol regressions with Node 22 or newer:

```sh
node --test javascript/experimental-layout/demo/protocol.test.mjs
```

They exercise a failed switch after a hidden worker commit and downloads
that overlap an edit. No browser or server is needed for these checks.

From a checkout with the demo prerequisites, Firefox, GeckoDriver and the
test Python environment installed, run the whole check (including build,
temporary server, pointer actions and downloaded package inspection):

```sh
.venv/bin/python tools/serve_layout_demo.py --smoke
```

With the demo server running, start `geckodriver --port 4444` in another
terminal. Run the smoke from the checkout root with Node 22 or newer and a
Python environment containing `python-docx`:

```sh
PYTHON=.venv/bin/python node javascript/experimental-layout/demo/smoke.mjs http://127.0.0.1:8000/
```

Optionally set `FIREFOX_BIN` to the Firefox binary if GeckoDriver cannot find
it. `PYTHON` defaults to `python3`. The smoke checks real pointer actions,
positioned outlines, cross-page selection, soft-wrap affinity, and stale
messages in the fixed sample. It opens the DOCX fixture, inserts, replaces,
deletes, and tests a preview that fails to reopen. It downloads each state
from Firefox and independently checks text with `python-docx`, exact
source and rollback bytes, and every ZIP payload other than the edited main
document part. Firefox downloads to a run-owned directory in `$HOME` so
Firefox Snap can see it; the smoke removes it on completion or failure.

## Geometry flow

The worker owns `ExperimentalLayoutSession` and its current physical
snapshot. `layoutPages` provides packed positioned glyphs and row geometry;
the worker transfers their buffers. The main thread positions SVG outline
instances with the row origin and baseline plus the glyph offsets. It scales
font units into 1/64 pt and flips the outlines' y axis, not the glyph
positions. The atlas is generated by glyph ID from the exact same font,
including glyphs selected only by OpenType shaping. No browser text
measurement, browser shaping, or Canvas text rendering is involved.

An inverse SVG transform maps pointer coordinates to page-local 1/64 pt.
The worker calls `hitTest`, `caretBox`, and `selectionRects`; at soft
wraps it picks the caret affinity matching the hit row. A drag across a
gap keeps the last valid selection. Layout IDs, snapshot revisions, and
pointer request IDs keep old geometry from repainting after a reflow.
During fast switching, an intermediate worker commit stays hidden unless
the newest switch fails. In that case the demo paints the worker's last
committed layout so the displayed page and its edit targets stay aligned.

For DOCX, `openPages` supplies the source-bound handle, page spec, and
geometry. The worker resolves each edit against the current selection and
source revision, calling `previewInsert` or `previewReplace`. Only a preview
that successfully reopens replaces the retained bytes and geometry. On
failure the worker reports the source and scalar location without replacing
the active snapshot. Downloads return the bytes for the exact revision
that was visible when clicked, even if an edit completes first.
