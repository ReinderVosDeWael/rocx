# Branded service report

This synthetic report starts with an independently generated, unsigned
python-docx template. The body title contains `{{title}}`; the default header
contains the Northstar brand. The examples fill the title and insert a table
with a shaded, bold header row from the same small [dataset](https://github.com/ReinderVosDeWael/rocx/blob/main/examples/branded_report_data.tsv).

Download the [template](branded_report_template.docx) and
[finished report](branded_report_output.docx). The
[Rust](https://github.com/ReinderVosDeWael/rocx/blob/main/examples/branded_report.rs)
and [Python](https://github.com/ReinderVosDeWael/rocx/blob/main/examples/branded_report.py)
programs use documented declarative template APIs.

From the repository root, after the usual Rust and Python setup:

```sh
cargo run --locked --example branded_report -- /tmp/branded-rust.docx
python examples/branded_report.py /tmp/branded-python.docx
python -m pytest examples/test_branded_report.py
```

The test verifies exact Rust/Python output bytes, the checked-in output asset,
title and table content, the unchanged source package, and exact header-part
payloads. It also checks that neither example overwrites the template.
The template was generated by
[`branded_report_template.py`](https://github.com/ReinderVosDeWael/rocx/blob/main/examples/branded_report_template.py)
using python-docx. Regenerating it may change ZIP metadata; regenerate the output
and rerun the parity test if the template changes.

This is a fixture-specific preservation check, not a guarantee for arbitrary
templates. rocx writes DOCX content; Word or another viewer controls rendering
and pagination. rocx does not evaluate fields. See the
[template recipe](recipes.md#edit-an-existing-document) and
[compatibility](compatibility.md) for supported edits and preservation limits.
